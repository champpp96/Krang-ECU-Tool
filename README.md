# Krang ECU Tool — Android อุปกรณ์ที่ Android มองเห็น แสดง VID/PID และขอสิทธิ์ USB ได้
- เพิ่มการนำเข้าไฟล์ `.BIN` และ `.XDF` แบบอ่านอย่างเดียว (จำกัด 128 MB ต่อไฟล์)
- สำรองไฟล์ต้นฉบับลงพื้นที่ส่วนตัวของแอป พร้อมคำนวณ SHA-256 และตรวจว่าสำเนาตรงกับต้นฉบับ
- แสดงขนาดไฟล์และ 16 ไบต์แรกของ BIN; สำหรับ XDF แสดง title และจำนวน XDFTABLE ที่อ่านได้
- ส่งออกสำเนาสำรองผ่าน Android file picker พร้อมตรวจ SHA-256 ระหว่างส่งออก
- ปิด Android Auto Backup ของแอปเพื่อไม่ให้ไฟล์ BIN/XDF ภายในถูกนำไปสำรองโดยระบบโดยไม่ตั้งใจ
- Workflow สำหรับสร้าง APK ผ่าน GitHub Actions และสร้าง SHA-256 ของ APK

## ข้อจำกัดที่ต้องเข้าใจ
- การอ่าน XDF ในรุ่นนี้เป็นเพียง metadata inspection ไม่ได้ถอดรหัส conversion, address, endian, scaling หรือ map definition
- ยังไม่มีการตรวจว่า XDF ตรงกับ BIN หรือ ECU รุ่นใดโดยอัตโนมัติ
- ยังไม่มี USB-to-Serial driver / serial transport สำหรับอะแดปเตอร์เฉพาะรุ่น
- ยังไม่มี ECU protocol ที่ยืนยันแล้ว จึงยังอ่าน Live Data หรือ DTC จากรถจริงไม่ได้
- ยังไม่มี checksum validation ของ firmware, ECU write/flash หรือขั้นตอน recovery
- หน้าจอแก้ไขตารางจูนยังเป็น placeholder; ไม่มีการแก้ไข BIN หรือส่งคำสั่งเขียน ECU

**อย่าใช้ต้นแบบนี้เขียน ECU จริง** จนกว่าจะยืนยันรุ่นกล่อง โปรโตคอล อะแดปเตอร์ checksum วิธีสำรอง/กู้คืน และทดสอบบนชุดทดลองที่ปลอดภัย

## วิธีนำเข้าและสำรองไฟล์
1. เปิดเมนู **จัดการไฟล์จูน** แล้วเลือกไฟล์ `.BIN` หรือ `.XDF`
2. กด **นำเข้าและสำรองต้นฉบับ** แอปจะคัดลอกไฟล์เข้า private app storage และตรวจ SHA-256
3. ตรวจชื่อไฟล์ ขนาด และค่า SHA-256; XDF จะแสดง title และจำนวนตารางที่พบเท่านั้น
4. กด **ส่งออกสำเนาสำรองไปยังมือถือ** แล้วเลือกโฟลเดอร์ปลายทางใน Android file picker
5. เก็บสำเนาไว้อย่างน้อยสองแห่งก่อนทำงานกับไฟล์จูน

ข้อควรระวัง: สำเนาภายในแอปจะถูกลบเมื่อถอนการติดตั้งแอปหรือเคลียร์ข้อมูลแอป จึงควรส่งออกสำเนาไว้ภายนอกทันที การตรวจ SHA-256 ยืนยันว่าไฟล์สำเนาเหมือนกับไฟล์ที่นำเข้า ไม่ได้ยืนยันว่า BIN ถูกต้องกับ ECU หรือปลอดภัยสำหรับการแฟลช

## สร้าง APK ผ่าน GitHub Actions
1. สร้าง repository ใหม่บน GitHub
2. แตก ZIP แล้วอัปโหลดไฟล์และโฟลเดอร์ทั้งหมดภายในโปรเจกต์ไปที่ระดับบนสุด (root) ของ repository ต้องมี `.github/workflows/android-build.yml` ที่ root
3. เปิดแท็บ **Actions** เลือก **Build Android APK** แล้วกด **Run workflow**
4. เมื่อ workflow สำเร็จ ให้ดาวน์โหลด artifact `KrangEcuTool-debug-apk`
5. แตก artifact จะพบ `app-debug.apk` และ `app-debug.apk.sha256`
6. ติดตั้ง APK บนมือถือ Android; หาก Android เตือน ให้ตรวจสอบว่า workflow สำเร็จจาก repository ของตนเองก่อนติดตั้ง

หาก Build ล้มเหลว ให้ส่งข้อความ error ช่วงท้ายของ Actions มาเพื่อวิเคราะห์ โดยไม่ส่ง token หรือรหัสผ่าน

## ทดสอบหน้า USB OTG บนมือถือ
1. ติดตั้ง APK ที่ Build สำเร็จ
2. เปิดเมนู **เชื่อมต่อ ECU** โดยยังไม่ต่อเข้ากับ ECU รถ
3. เสียบอะแดปเตอร์ USB ผ่านสาย OTG แล้วกด **ตรวจหาอีกครั้ง**
4. ตรวจว่าระบบเห็น VID/PID และลองกด **ขอสิทธิ์ USB**
5. บันทึก VID/PID, ชื่ออะแดปเตอร์ และข้อความสถานะ เพื่อใช้เลือกไดรเวอร์ในขั้นต่อไป

การทดสอบนี้ตรวจเฉพาะการมองเห็นอุปกรณ์ USB/การขอสิทธิ์ ไม่ได้ยืนยันว่าอะแดปเตอร์สื่อสารกับ ECU ได้
